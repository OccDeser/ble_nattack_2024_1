\section{Automation and Universality}

% 在上一小节中我们介绍了如何通过一组通用的rule建模攻击者的暴力破解能力，在这一小节中，我们将介绍如何将我们的方法应用于协议建模。为了尽可能方便建模地建模协议，我们拓展了Tamarin的语法，引入了新的关键词，以标明协议中需要重点关注的低熵密钥。同时，实现了一套编译工具 Tamarin-Compilation-Tool，将拓展的Tamarin语法编译为Tamarin prover可识别的形式化模型。此外，为了配合oracle的建模，我们的工具支持分析rule中的消息生成关系，自动化地为模型添加消息派生fact。然后，为了模型的自动化验证，我们的编译工具支持为oracle rule根据不同的协议情况，来定义搜索边界，以避免分析不终止。
In the preceding section, we detailed the methodology for modeling the attacker's brute-force capabilities using a set of general rules.
This section elucidates the application of our approach to protocol modeling.
To streamline the modeling of protocols, we extended Tamarin Prover's syntax by introducing new keywords that explicitly identify low-entropy keys requiring special attention within the protocol.

We also developed a compilation tool named Tamarin-Compilation-Tool which translates the extended Tamarin syntax into a formal model recognizable by the Tamarin Prover.
In support of the key cracking oracle model, our tool analyzes derivation relationships between variables and automatically incorporates message derivation facts into the model.

To facilitate automated model verification, our Tamarin-Compilation-Tool supports the definition of search boundaries for oracle rules tailored to different protocol scenarios.
This feature is crucial for preventing non-terminating analysis, ensuring that the verification process completes efficiently and reliably.

To facilitate our methodology, we introduced a new operator ``:='' and a keyword ``\verb|`L`|''.
These syntax elements streamline the marking of low-entropy variables.
In the revised syntax, as depicted in \autoref{fig:rule-plus-demo}, the low-entropy annotation for the variable (line 3) is defined within the let block.

This annotation is subsequently translated by the compilation tool into the fact $\text{\TFact{EntropyLow}}(foo)$ on the right-hand side of the rule.

\subsection{ Design of Tamarin-Compilation-Tool }
% Tamarin-Compilation-Tool 被设计用来为Tamarin prover生成可识别的形式化模型。执行\autoref{sec:oracle-modeling}定义的模型需要提供\TFact{EntropyLow} 和 \TFact{MDerive} facts，这些facts由我们的Tamarin-Compilation-Tool生成。
The Tamarin-Compilation-Tool has been developed to create formal models that are compatible with the Tamarin prover.
To implement the model specified in \autoref{sec:oracle-modeling}, it is necessary to supply the \TFact{EntropyLow} and \TFact{MDerive} facts.
These facts are generated by our Tamarin-Compilation-Tool.
As shown in \autoref{fig:design-of-compilation-tool}, Tamarin-Compilation-Tool contains 4 modules:

% Model parsing: 给定一个低熵标记的模型代码作为输入，这个模块复杂将模型代码解析为结构化的数据，方便后续模块处理。
\textbf{Model parsing:} given the code of a low-entropy annotated model as input, this module parses the model code into structured data, facilitating subsequent processing by other modules.

% Label interpretation:Tamarin-Compilation-Tool 然后根据模型中的低熵表情转译为对应变量的\TFact{EntropyLow} fact，添加到模型中。
\textbf{Label interpretation:} the Tamarin-Compilation-Tool subsequently converts low entropy annotations into corresponding \TFact{EntropyLow} facts for the relevant variables, integrating them into the model.

% Derivation generation: 这个模块负责分析rule中的消息生成关系，并生成消息派生fact。
\textbf{Derivation generation:} this module analyzes the message derivation relationships within the rules and generates \TFact{MDerive} facts.

% Oracle complement: 这个模块负责将密钥破解Oracle添加到模型中，并为其添加一些合理的restrictions，以确保模型的自动化验证不会陷入无法终止的状态。
\textbf{Oracle complement:}  the module adds the key-breaking oracle to the model and incorporates reasonable restrictions to prevent the model's automated verification from entering a non-terminating state.


\subsection{ Term and fact sequence notations }
% 在翻译后的多重集重写系统中的term都与翻译之前保持一致，例如图8中的$x$在翻译后的规则中仍然是$senc('hello',k)$。为了方便描述，我们为term定义一些操作。对于一个term $t$,$\delta(t)$ represents the sequence of all sub-terms that can be deconstructed from $t$.
% $\rho(t)$代表了构建t所需的所有的无法被解构的term。
In the translated multiset rewriting system, each term remains consistent with its original form.
For instance, in \autoref {fig:rule-plus-demo}, $x$ in the translated rule continues to be represented as $senc('hello',k)$.
To aid in description, we define the following operations.
For a given term $t$, $\delta(t)$ denotes the sequence of all sub-terms that can be deconstructed from $t$.
Conversely, $\rho(t)$ represents all the terms necessary to construct $t$ that cannot be deconstructed.

% 我们denote $\llbracket e_1, e_2, \ldots, e_n \rrbracket$ 为一个sequence，其中所有$e_i$的类型必须一致，可以是 term、fact 或者 sequence。
% 在上述符号的基础之上，我们可以将多重集重写规则的left-hand side和right-hand side使用sequence来表示。例如 $F_L \Longrightarrow F_R$ 代表了一条规则，其中$F_L$ 和 $F_R$ 是fact的sequence。
% $S_1 \circ S_2$ 表示两个sequence $S_1$ 和 $S_2$ 的连接。$S_1 \setminus S_2$ 会生成一个新的sequence，其中包含了所有在$S_1$中但不在$S_2$中的元素。$F$ 是一个fact的sequence，$\tau(F)$ 代表了所有fact中的term的sequence。
% 对于由$\llbracket t_1, t_2, \ldots, t_n \rrbracket$构成的term sequence$T$,$\varepsilon(T)$代表了$\delta(t_1) \circ \delta(t_2) \circ \ldots \circ \delta(t_n)$。
% $c(T)$与$v(T)$分别代表了$T$中的所有常量term例如字面量和公共term和变量。
We denote $\llbracket e_1, e_2, \ldots, e_n \rrbracket$ as a sequence where all $e_i$ must be of the same type, which can be a term, fact, or sequence.
With the sequence notation, we can represent the left-hand side and right-hand side of a multiset rewriting rule using sequences.
For instance, $[F_{L}] \Longrightarrow [F_{R}]$ denotes a rule where $F_{L}$ and $F_{R}$ are sequences of facts.
We additionally define operations for sequences.
$S_1 \circ S_2$ represents the concatenation of two sequences $S_1$ and $S_2$.
The operation $S_1 \setminus S_2$ generates a new sequence containing all elements present in $S_1$ but absent in $S_2$.
Let $F$ be a sequence of facts, and $\tau(F)$ represents the sequence of terms extracted from all facts.
For a term sequence $T$ composed of $\llbracket t_1, t_2, \ldots, t_n \rrbracket$, $\varepsilon(T)$ denotes the sequence $\delta(t_1) \circ \delta(t_2) \circ \ldots \circ \delta(t_n)$.
$c(T)$ outputs a sequence of all constant terms, i.e.~literals and public terms in $T$.

% 在上述的notations的基础之上，我们将提出如何翻译一个低熵标记的多重集重写系统。
Based on the aforementioned notations, we propose to detail the translation of a low-entropy labelled multiset rewriting system.

% 标签翻译 给低熵term的标记，准确来说并不属于多重集重写系统，引入它是为了方便在现有的规则中标注出低熵term。对于规则$F_L \Longrightarrow F_R$，我们使用$T_{Low}$代表这条规则中被标记的低熵term，$T_{Low} \subseteq \varepsilon(\tau(F_L)) \circ \varepsilon(\tau(F_R))$。我们定义低熵标签被翻译的规则如下：
% 其中，为了简洁，我们使用$\text{LE}(T_{Low})$来代表一个序列，that consists of fact $\text{\TFact{EntropyLow}}(t)$ for each term $t$ in $T_{Low}$.
\textbf{Label interpretation:} 
Labels of low-entropy terms are not inherently part of the multiset rewriting system; it is introduced to facilitate the identification of such terms within existing rules.
For a given rule $[F_L] \Longrightarrow [F_R]$, $T_{Low}$ denotes the set of low-entropy terms labeled in the rule, where $T_{Low} \subseteq \varepsilon(\tau(F_L)) \circ \varepsilon(\tau(F_R))$.
The translated version of such rule with low-entropy labels is shown as follows:
\[
    [F_L] \Longrightarrow [F_R \circ \text{\textsf{LE}}(T_{Low})]
\]
where, for brevity, we use $\text{\textsf{LE}}(T_{Low})$ to represent the sequence $\llbracket \text{\TFact{EntropyLow}}(t_i) \rrbracket$ for each term $t_i$ in $T_{Low}$.

% 派生生成 对于规则$[F_L] \Longrightarrow [F_R]$，$\tau(F_R)$代表了这条规则执行之后存在的term，而$\varepsilon(\tau(F_L))$则代表了这条规则所有的已知term。因此，我们可以使用$\tau(F_R) \setminus \varepsilon(\tau(F_L))$来表示规则执行所派生出的新term。我们定义添加消息派生事实之后的规则如下：
% 这里我们使用$\text{\textsf{MD}}(T)$来表示消息派生事实序列，其中序列T的每个元素都是一个term的消息派生事实。对于单个term $t$，$\rho(t) \setminus c(\rho(t)) $ 包含了构建$t$所需的所有变量term。
% 这里我们使用$\text{\textsf{MD}}(T)$来表示来表示使用序列T中每个term作为计算结果的消息派生事实。对于单个term $t$，$\rho(t) \setminus c(\rho(t)) $ 包含了构建$t$所需的所有变量term。那么$\text{\textsf{MD}}(T)$可以被定义为$\text{\TFact{MDerive}(\langle \rho(t) \setminus c(\rho(t)) \rangle, t)}$ for each term $t$ in $T$。
\textbf{Derivation generation:} 
Given the rule $[F_L] \Longrightarrow [F_R]$, $\tau(F_R)$ denotes the terms present within the rule after executing, whereas $\varepsilon(\tau(F_L))$ represents all possibly accessible terms before the execution.

Thus, $\tau(F_R) \setminus \varepsilon(\tau(F_L))$ can be used to represent the new terms derived during the execution of the rule.
We define the rules incorporating message derivation facts as follows:
\[
    [F_L] \Longrightarrow [F_R \circ \text{\textsf{MD}}(\tau(F_R) \setminus \varepsilon(\tau(F_L)))]
\]
Here, $\text{\textsf{MD}}(T)$ denotes a sequence that consists of message derivation facts.
For an individual term $t$, $\rho(t) \setminus c(\rho(t) $ contains all variable terms needed to construct it.
Hence $\text{\textsf{MD}}(T)$ can be defined as 
% $\text{\TFact{MDerive}}(\langle \rho(t) \setminus c(\rho(t)) \rangle, t)$ for each term $t$ in $T$.
$\llbracket \text{\TFact{MDerive}}(\langle \rho(t_i) \setminus c(\rho(t_i)) \rangle, t_i) \rrbracket$, where $t_i \in T$.
